ORCA · I4 · CLOSE, DISMISS AND ICON BUTTONS

The X is a 28px rounded square, last in its row, aligned to the first line.

There are only two places in Orca with a visible X: a toast and a dismissable card. Everything else closes by Esc, clicking outside, or a Back link. A close button is an ordinary icon button: same size, radius and states as Copy or More. It is never a circle, never floats over a corner, never sits left of the actions.

1 · Component

  • <button class="ib" aria-label="Close"> for toasts, aria-label="Dismiss" for cards. Real <button>, Tab-reachable.
  • width: 28px; height: 28px; border-radius: 8px; display: grid; place-items: center; flex: none. The hit area is the full 28×28 (above the WCAG 2.2 24px minimum); ≥ 8px from any neighbor.
  • Glyph: inline SVG, width/height 13, stroke-width 2.2, stroke-linecap: round, stroke: currentColor. Not the "×" character, not an icon font.
  • title="Close (Esc)" only on toasts that also respond to Esc.

2 · Placement rules

  • Always the last child of its row, rightmost. Primary and secondary actions sit left of it with 8px gap.
  • In multi-line containers it aligns to the first line (align-items: flex-start on the row), never vertically centered on the whole block.
  • Negative margins pull the 28px box outward so the glyph, not the box, lines up with the container's padding edge. Toast: -2px -4px 0 0. Card header: -3px -6px -3px 0.
  • It lives inside the container's padding box. Never position: absolute over the corner, never overlapping the border.

3 · Behavior

  • Toast X: removes the toast with a 140ms fade + 4px drop; focus returns to the element that was focused before the toast appeared, else the first card.
  • Card X: removes the card (collapse height over 200ms, then remove); toast "Dismissed · Undo" for 6s. Only resolved cards (ended, moved to Cursor) get an X. Pending requests never do: you Approve or Deny them.
  • Reduced motion: no fade or collapse; remove instantly.
