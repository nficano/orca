ORCA · I6 · INTERACTIONS AND STATE MACHINE

What every click, key and timer does.

The main process owns state; renderers only send intents and render snapshots. No renderer ever decides a request on its own. Anything not listed here does nothing: no hover-to-act, no swipe, no auto-approve.

3 · Surfaces

Tray icon

  • Left click: toggle popover. Opening restores the last rail section and account tab; scroll resets to top.
  • Right click: native menu: Open Orca · Pause notifications for 1 hour · Settings… · Quit Orca (⌘Q). No custom HTML menu.
  • Icon: template image 18×18, two states only: idle and "has pending" (filled). Count via setTitle. No animation.

Popover

  • Open: opacity 0→1 and translateY −4px→0, 120ms ease-out. Close: 90ms fade, no slide. Reduced motion: instant.
  • On open, focus goes to the oldest pending card (outline only when opened by keyboard).
  • Blur hides it, except while the Touch ID sheet is up or a native picker menu is open.
  • New request while open: card inserts at its sorted position with a 160ms rise; list never jumps under the pointer: if the user is hovering a card, inserts above it are held until the pointer leaves the list ("2 new above" chip at top).

Request card

  • Click on title or command opens approval detail. Click on buttons acts. Click elsewhere on the card focuses it only.
  • Right click: context menu at pointer, flipped to stay inside the popover: Open in Cursor ⌘O · Copy command ⇧⌘C · Snooze 15 minutes · ── · Always allow…
  • Command block: one line with ellipsis; Space or click expands to 2 lines + "Show all" (I-11 edge cases).
  • Countdown label: "Moves to Cursor in Nm", per second under 60s. Text and bar share one 1Hz timer.

Approval detail

  • Replaces the list inside the popover (no new window). "‹ Inbox" returns, keeping list scroll.
  • Header shows "N of M" and ↑ ↓ buttons; disabled at ends.
  • Steps: compound commands split on && ; ||; each step numbered with its one-line explanation; risky flags highlighted with <mark> r3.
  • Resolved while open (another surface answered): banner "Answered in quick answer", buttons removed, auto-advance to next in 1.5s.

Always-allow sheet

  • Anchored above the split button. 344 wide, r14, padding 8. Esc / outside click cancels without approving.
  • Rows: Approve once ↩ · divider · per-step pattern (code) · scope radios (repo, all accounts / this account, all repos) · "Allow and approve" primary.
  • Preview line: "Would have covered N earlier requests" from history; hidden when 0.
  • Red tier: pattern rows disabled with "High-risk commands can't be allowed always."

Quick-answer panel

  • Separate BrowserWindow, 640 wide, height fits content (max 480), centered horizontally, top at 22% of the active display. Panel-type window: doesn't steal focus from the app beneath on close.
  • Shows oldest unanswered question across accounts. After answering: next question cross-fades in 120ms. Queue empty: "All clear" line 600ms, then closes.
  • Opened with nothing waiting: shows "Nothing waiting" 900ms and closes.

Notifications

  • Request: title = session title, subtitle = "High risk · wants to force-push", body = raw command (plain). Actions: Review (opens popover detail), Deny. Approve is never offered for high risk in a banner.
  • Medium / low: actions Approve, Deny.
  • Question: actions = up to 3 options from ask_user (system "Options" dropdown) + Reply (hasReply).
  • One notification per request, grouped by account; removed with notification.close() the moment the request resolves anywhere.

Batch row and stalled sessions

  • Batch row lists low-risk requests with checkboxes; anything reading outside its worktree starts unticked with a reason. "Approve N" re-checks tiers in main at click; a request that changed tier is skipped and reported.
  • Stalled: Stop… opens a 280-wide confirm popover anchored to the button: "Stops the agent process. Work so far is kept." Cancel · Stop. Stop sends SIGINT, then SIGTERM after 5s.

Toasts

  • One visible at a time, bottom of the popover, 16px inset. A newer toast replaces the older; errors are never replaced by info.
  • Durations: success 4s, undo 8s, error until closed. Hover pauses the timer.
  • role="status" for info, role="alert" for errors.

5 · IPC contract (renderer ↔ main)

// renderer → main (ipcRenderer.invoke), all return { ok, error? }
'request:decide'   { id, decision: 'allow'|'deny', reason?, rule?: { pattern, scope: 'repo'|'account' } }
'question:answer'  { id, optionIndex? , text? }
'request:snooze'   { id, minutes: 15 }
'session:stop'     { sessionId }
'session:resume'   { sessionId, prompt }
'window:focus'     { sessionId }            // Cursor window via extension
'rule:undo'        { ruleId }
'settings:set'     { key, value }
// main → renderer (webContents.send), full snapshots, not diffs
'inbox:snapshot'   { pending[], running[], done[], problems[], counts }
'toast'            { kind: 'success'|'undo'|'error', text, actions[] }

// invariants
// 1. A request id is decided at most once; second decide → { ok:false, error:'already-resolved' }.
// 2. Renderer disables controls on send and re-enables only on error.
// 3. Snapshots are idempotent; renderer keys rows by id so focus survives updates.
// 4. Every decide is appended to ~/Library/Application Support/Orca/decisions.jsonl.
